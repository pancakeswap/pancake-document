# Swap よくある質問 (FAQ)

## スワップ

### Exchange V3の新機能は何ですか？

* 集中流動性 — 流動性が最も活発に取引される価格レンジに集中されます。これにより：
  * トレーダーの取引スリッページが低下します
  * 流動性プロバイダーのLP手数料報酬が増加する可能性があります
* 柔軟な取引手数料体系 — 流動性プロバイダーは流動性ペアの作成または流動性提供時に複数の取引手数料ティアから選択できます
* カスタマイズ可能な価格レンジ — 流動性プロバイダーはどの価格レンジに流動性を提供するかを選択できます
* 代替不可能な流動性ポジション — 各流動性ポジションは設定（価格レンジなど）に対応した固有のIDを持ちます。そのため、同じ取引ペアで異なる設定と流動性量の複数のポジションを作成・維持できます
* 後方互換性 — v3 Exchangeはレガシーのv2とStableSwapの流動性ペアも活用して常に最良の取引ルートを提供します
* 内蔵指値注文 — 上級ユーザーは流動性提供のカスタマイズ可能な価格レンジを活用して、価格が目標に達したときにすべてのトークンを希望するものに変換する指値注文を実質的に作成できます



### Exchange V3に独自のトークンを追加できますか？

誰でもV3に流動性を預けることで流動性プールを作成できます。

ただし、現在以下のトークンはサポートされて**いません**：

* 転送手数料付きトークン
* リベーストークン

これらのトークンについては、Exchange V3に流動性を追加**しないでください**。資産が流動性ポジションに固まってしまう可能性があります。



### **なぜトランザクションが通らないのですか？**

PancakeSwapはDeFiアプリケーションであるため、スワップ、LP作成、ファームやプールへのステーキングなどのオンチェーントランザクションを完了するためにウォレットと連携します。

**ガス代**

そのため、まず**オンチェーントランザクションのガス代を支払うのに十分なBNBがあることを確認してください**。通常、ガス代はキュー内のトランザクション数に応じて変動し、トランザクションが多い場合は高いガス代が必要な場合があります。BNB Smart Chainのガス代は通常、BNBで数セントから数ドル程度です。[ガス代についての詳細はこちら](https://academy.binance.com/en/glossary/gas)。

**トランザクション手数料**

スワップがまだ通らず、スリッページを修正するよう求めるエラーが表示されている場合 — スワップしようとしているトークンに**トランザクション手数料や制限がある**かどうかを確認することをお勧めします。

BNB Smart Chain上のトークンが契約内に**トランザクション手数料**を含めることは珍しくありません。これらの手数料はバーンのための資金調達、フェアローンチプロジェクトの財務省への資金供給などに使用されます — 例えば、[このAPXトークンはすべてのトランザクションに1%の税金](https://apollox-finance.gitbook.io/apollox-finance/apx-token/tax)が適用されてバーンアドレスに送られ、より多くのトランザクションがより多くのバーンを意味し、APXトークン保有者に価値をもたらします。

トランザクション手数料が内包型（スワップ量の一部がアドレス以外の場所に送られるため、推定入力量に対して出力が期待より少なくなる）か外付型（追加のトランザクションが必要となり、推定出力量に対して入力が期待より多くなる）かにかかわらず、トランザクションに署名するために同意した入出力量に影響を与えます。多くの場合、税金により入出力要件を満たすことができずトランザクションが失敗します。

**トランザクション手数料がある場合のスワップ**

トークンをスワップする前に、ウェブサイトを訪問してトランザクション手数料メカニズム（多くのプロジェクトが「税金」と呼ぶもの）があるかどうかを確認してください。ある場合は、トランザクション手数料に対応するのに十分なスリッページを設定してください — 例えば、5%のトランザクション手数料がある場合、スリッページは最低でも5%に加えて取引量とトークンの流動性に応じた通常の取引スリッページを設定する必要があります（例：5.5%〜6%）。

一部の詐欺を含む極端なケースでは、一部のトークンはチェーン上のほとんどまたはすべての転送をブロックしたり、特定のアドレスのみが売却できるようになっていたりします。その場合、トークンのスワップを成功させることはできません。スワップしようとしているトークンについて調べ、手数料と制限を把握してください！



### 新しいSwapインターフェースはv2またはStableSwapの流動性を使用しますか？

はい。新しいSwap v3はPancakeSwap v3、v2、StableSwapの流動性を使用して最良の取引ルートを取得します。



### スプリットルーティングとは何ですか？

Swap v3では、最良のレートでトレードを実行するために、トレードが複数のルートに分割される場合があります。

トレードのルーティング方法の詳細を確認するには、「Route（ルート）」セクションの「v」ボタンをタップして展開し詳細を表示します。

詳細は[こちら](../pancakeswap-exchange/fees-and-routes.md#customize-routing-preferences)をご覧ください。



### 特定の流動性ソースをカスタマイズまたは無効にする方法は？

新しいSwap v3はPancakeSwap v3、v2、StableSwapの流動性を使用して最良の取引ルートを取得します。ただし、特定の流動性ソースを通じてトレードをルーティングしたくない場合は、カスタマイズまたは無効にできます。

取引ルートを表示しているときに「Customize Routing（ルーティングをカスタマイズ）」ボタンをクリックします。またはSwapインターフェースの右上にある歯車アイコン⚙️をクリックして「Customize Routing（ルーティングをカスタマイズ）」を選択します。

「Customize Routing（ルーティングをカスタマイズ）」ポップアップ内で、使用したい流動性ソースを選択できます。またはマルチホップを完全に無効にすることもできます。

注意：マルチホップを無効にすると、特定の取引ペアでスリッページが増加したり取引レートが悪化したりする可能性があります。慎重に進めてください。

詳細は[こちら](../pancakeswap-exchange/fees-and-routes.md#customize-liquidity-sources)をご覧ください。



## 流動性

### 手数料ティアとは何ですか？正しいものを選ぶには？

Exchange v3では、流動性を提供する際に、同じトークンペアに対して複数の異なる取引手数料（0.01%、0.05%、0.25%、1%）から選択できます。

例えば、CAKE-BNBの場合、0.25%のペアが存在する可能性があり、すべての取引に0.25%の取引手数料が適用されます。ただし、一部の流動性プロバイダーはより良い見積もりを提供してより多くの取引量を引き付けるために、0.05%の手数料レートでCAKE-BNBの取引ペアに流動性を提供することを選択するかもしれません。

どの取引手数料設定を選択するかに「正解」はありません。取引ペア内のトークンによって異なります。通常、ボラティリティが高いトークンはボラティリティによるインパーマネントロスをより良く補填するために高い取引手数料を持つべきです。一方、ステーブルコインのようなトークンは価格変動が小さくインパーマネントロスも少ないため、取引手数料は低くなるべきです。

トークンペアを選択すると、「流動性を追加」インターフェースが自動的に最も人気のある手数料ティアを選択します。



### なぜ2つの預け入れトークンのUSD価値が同じでないのですか？

Exchange V3では、流動性ポジションの原資産は常に等しいUSD価値を持つとは限りません。ポジションの価格レンジ設定とペアの現在価格によって異なります。

実際、ポジションがレンジ外になると、すべてのトークンが1つの資産に変換されます。さらに、現在の価格をカバーしない価格レンジに流動性を提供して1種類の資産のみを預けることもできます。続きを読んでください⬇️



### 流動性ポジションがレンジ外になるとどうなりますか？

現在の価格がポジションで定義された価格レンジ外になると、取引手数料報酬を獲得できなくなります。

さらに、価格状況の方向によって、すべてのトークンが1つの資産に変換されます。

例えば、CAKE/BUSDのポジションがCAKE1枚あたり3 BUSDから5 BUSDの価格レンジで設定されている場合。CAKEの価格がBUSDで5以上になると、ポジション内のすべての資産がBUSDに変換され、逆も同様です。

価格がレンジに戻った場合、再び取引手数料報酬を受け取り始めることに注意してください。追加のアクションは必要ありません。



### 常に小さいレンジで流動性を提供した方が良いですか？

小さい価格レンジで流動性を提供すると、特定の価格レンジに流動性を集中させ、その価格レンジ内の総流動性に対する相対的なシェアを高め、より多くの取引手数料報酬を得る可能性があります。

ただし、アクティブな流動性ポジションのみが取引から取引手数料報酬を獲得できることを覚えておいてください。つまり、現在の取引価格が流動性ポジションで定義された価格レンジ内にある場合にのみ報酬を獲得できます。



### ポジションが常にレンジ内にあり手数料報酬を獲得できるよう自動調整する方法はありますか？

PancakeSwap v3はBNBチェーンとEthereumでZapを介したワンクリック流動性預け入れをサポートしています。

### LP手数料報酬はExchange v2のように自動的に複利になりますか？

いいえ。

Exchange v3では取引手数料報酬を手動で請求する必要があります。ポジション詳細ページで行えます。流動性ページですべてのv3流動性ポジションを確認できます。



### LP APRに影響する要因は何ですか？

Exchange v3では、LP手数料報酬のAPRは流動性ポジションによって異なります。以下の要因に基づいています：

* 取引量\
  \- より多くの取引量がより多くの手数料報酬を生み出します
* 流動性ペアの手数料ティア\
  \- 高い手数料ティアは個々の取引からより多くの手数料報酬を生み出します
* 預けたトークン数\
  \- ポジション内のトークンが多いほど総アクティブ流動性に対する相対的なシェアが大きくなり、取引からより多くの取引手数料報酬を得られます
* 選択した価格レンジ\
  \- 小さい価格レンジにより、同量のトークン預け入れでより高い集中度が得られ、総アクティブ流動性に対する相対的なシェアが大きくなり、取引からより多くの取引手数料報酬を得られます
* 現在アクティブな流動性量\
  \- 自分と同じレンジに流動性を集中させる多くのユーザーがいる場合、総流動性に対する相対的なシェアが小さくなるため、より少ない取引手数料を獲得します
* 流動性ポジションがアクティブかどうか\
  \- アクティブな流動性ポジションのみが取引手数料報酬を獲得します



### v2流動性を提供できますか？

v2流動性の提供はもはや推奨されません。効率を向上させる新機能を活用するためにv3流動性の使用をお勧めします。

v2流動性の追加を進めたい場合：

* トークンペアにv3プールがないか、v3の最大プールよりv2の流動性が多い場合、「V2流動性を追加」が表示されます。クリックしてv2流動性の追加に切り替えてください
* またはURLに`/v2`を使用して常にv2流動性提供を使用できます



### 作成したばかりのペアに流動性を追加できないのはなぜですか？

レガシーExchange V2（すべてのUniSwap V2フォークに存在するバグ）により、ペアが以下の状態の場合、通常のPancakeSwap流動性UIとそのコントラクト呼び出しを使用して流動性を追加できません：

* 初期流動性を預けずに初期LPトークンをミントせずにFactoryV2の`createPair`を呼び出してペアが作成された場合
* その後、ペア内のトークンの1つが`sync`を呼び出しながらプールコントラクトに手動で転送された場合

{% hint style="info" %}
最近、BNBチェーン上のPancakeSwap Exchange V2でこのような攻撃が増加しています。

初期流動性を追加してペアを作成する際には、当社のUIを使用してトークンの取引ペアを作成することを強くお勧めします。
{% endhint %}

ChefたちがこのIssue解決に取り組んでいる間、BscScanを使用してこの問題を解決するステップバイステップガイドをご紹介します：

#### プールアドレスとそのBscScanページを特定する

<div align="left"><figure><img src="https://raw.githubusercontent.com/pancakeswap/pancake-document/en/.gitbook/assets/cannot%20add%20v2%20liquidity-error%20pump.jpg" alt="" width="280"><figcaption></figcaption></figure></div>

ペアが影響を受けている場合、エラープロンプトに取引ペア/プールのBscScanページへのリンクが表示されます。

または、Factory V2（[Bsc](https://bscscan.com/address/0xca143ce32fe78f1f7019d7d551a6402fc5350c73#readContract)）に移動し、「Read Contract」、「6. getPair」を選択して取引ペアの2つのトークンのアドレスを入力し、「Query」をクリックします。戻り値フィールドにペアアドレスが表示されます。

#### どのトークンが預けられているか確認し、もう一方のトークンをペアに手動で転送する

![](https://raw.githubusercontent.com/pancakeswap/pancake-document/en/.gitbook/assets/image%20%28335%29.png)

BscScanのトークン残高フィールドから、プールに預けられているトークンを確認できます。通常、ペアトークン（WBNB、USDTなど）が預けられているはずです。

確認後、もう一方の資産をプールコントラクトに手動で転送する必要があります。好みのウォレットアプリでプールアドレスを受取人として入力して行えます。

任意の金額を転送できますが、これは実質的にプールへの「寄付」となります。LPトークンをミントせずに資産を流動性に転送することになります。そのため、この金額は最小限に抑えることをお勧めします。

{% hint style="warning" %}
重要：トークンを転送したら、すぐにプールで`sync()`を呼び出す必要があります。
{% endhint %}

BscScanの取引ペアページに移動し、「Write Contract」、「8. Sync」に移動して「Write」ボタンをクリックします。トランザクションを実行する前にウォレットを接続する必要があります。

トランザクションが確認されたら、PancakeSwap UIで後続の流動性を追加できます。

#### ローンチ価格を定義したい場合は？

トークンを転送してプールを修正しながら、プールをローンチ価格に調整する必要があります。

転送量は以下を使用して計算できます：

* `tokenInside`：すでにプールに転送されているトークン。通常はペアトークン（WBNB、USDTなど）です
* `tokenToSend`：プールに送信しようとしているトークン。通常はプロジェクトトークンです
* `tokenInside.price`：tokenInsideのUSD価格
* `tokenToSend.price`：tokenToSendのUSD価格（ローンチ価格）
* `pool`：V2プール

以下の式を使用します：

`amountToSend = tokenInside.balanceOf(pool) / tokenInside.decimal() * tokenInside.price / tokenToSend.price * tokenToSend.decimal()`

結果が0より小さい場合（通常はローンチ価格が非常に大きい場合）、最初にプールにより多くの`tokenInside`を預ける必要があります

### USDTを有効化/承認する前に承認をリセットする必要があるのはなぜですか？

Ethereumメインネットで操作する場合、USDTトークンは承認とトークン許可量の管理に異なるロジックに従います。&#x20;

そのため、支払い許可量が不足している場合。新しい許可量を設定する前に承認をリセットする必要があります。
