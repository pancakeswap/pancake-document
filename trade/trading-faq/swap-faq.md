# 兑换常见问题解答

## 兑换

### Exchange V3 有哪些新功能？

* 集中流动性 - 流动性将集中在交易最活跃的价格区间，这意味着：
  * 交易者的交易滑点更低
  * 流动性提供者可能获得更多 LP 手续费奖励
* 灵活的交易手续费结构 - 流动性提供者在创建流动性对或提供流动性时，可以在多个交易手续费档位之间进行选择
* 可自定义的价格区间 - 流动性提供者还可以选择他们想要提供流动性的价格区间
* 非同质化流动性头寸 - 每个流动性头寸都有其对应配置（如价格区间）的唯一 ID。因此，你将能够创建和维护多个使用相同交易对但配置和流动性数量不同的头寸
* 向后兼容 - v3 Exchange 还将利用旧版 v2 和 StableSwap 流动性对，以始终提供最佳交易路径
* 内置限价单 - 专业用户可以利用流动性提供中新的可自定义价格区间，有效地创建限价单，当价格达到目标时将所有代币转换为所需代币



### 我可以将自己的代币添加到 Exchange V3 吗？

每个人都可以通过在 V3 上存入流动性来创建流动性池。

但是，目前**不**支持以下代币：

* 转账征税代币 (Fee-on-transfer tokens)
* 弹性供应代币 (Rebase tokens)

对于这些代币，请**不要**在 Exchange V3 上添加流动性。你的资产可能会卡在流动性头寸中。



### **为什么我的交易无法完成？**

PancakeSwap 是一个 DeFi 应用程序，它与钱包交互以完成链上交易，用于兑换、创建 LP、在 Farm 和 Pool 中质押等。

**Gas 费**

因此，首先要**确保你有足够的 BNB 来支付**链上交易的 gas 费。通常，gas 费会根据队列中的交易数量而波动，如果交易较多，可能需要更高的 gas 费才能推动交易完成。在 BNB 智能链上，gas 费通常以 BNB 计价，范围从几美分到一美元不等。在[此处了解有关 gas 费的更多信息](https://academy.binance.com/en/glossary/gas)。

**交易费**

如果你的兑换操作仍然无法完成，并且显示错误要求你修改滑点——你可能需要检查你尝试兑换的代币是否**对交易有任何费用和限制**。

BNB 智能链上的代币在其合约中包含**交易费**的情况并不罕见，通常这些费用可用于销毁、为公平启动项目的国库提供资金——例如，这个 [APX 代币对每笔交易征收 1% 的税](https://apollox-finance.gitbook.io/apollox-finance/apx-token/tax)用于发送到销毁地址，这样更多的交易就意味着更多的销毁，为 APX 代币持有者积累价值。

对于交易费，无论是内含式（一部分兑换金额被发送到你地址以外的其他地方，因此输出少于估算输入的预期）还是外加式（需要从你的地址额外转账以发送额外代币，因此输入多于估算输出的预期），它都会影响你签署交易时同意的输入和输出金额。在许多情况下，由于税费，交易无法满足输入和输出要求。

**带交易费的兑换**

在兑换任何代币之前，请确保你已访问其网站，了解它们是否有交易费机制（或许多项目所称的_税_）。如果有，请确保你设置的滑点足以容纳交易费——例如，如果有 5% 的交易费，你的滑点至少要设置为 5% 加上正常的交易滑点（取决于你的交易金额和代币的流动性），比如说 5.5%-6%。

在某些极端情况下，包括一些骗局，有些代币甚至会阻止链上大部分或全部转账，或者只允许某些地址卖出，在这种情况下不可能成功兑换该代币。请务必了解你尝试兑换的代币，并留意任何费用和限制！



### 新的兑换界面是否使用 v2 或 StableSwap 流动性？

是的。新的兑换 v3 使用来自 PancakeSwap v3、v2 和 StableSwap 的流动性来获得最佳交易路径。



### 什么是分拆路由 (split routing)？

在兑换 v3 中，你的交易可能会被拆分为多条路径，以最佳汇率执行你的交易。

要查看交易路由方式的更多详情，请点击"Route"部分上的"v"按钮以展开并查看详情。

在[此处](../pancakeswap-exchange/fees-and-routes.md#customize-routing-preferences)了解更多。



### 如何自定义或禁用某些流动性来源？

新的兑换 v3 使用来自 PancakeSwap v3、v2 和 StableSwap 的流动性来获得最佳交易路径。但是，如果你不希望你的交易通过它们路由，你可以自定义或禁用某些流动性来源。

查看交易路由时，点击"Customize Routing"按钮。或点击兑换界面右上角的齿轮 ⚙️ 按钮并选择"Customize Routing"。

在"Customize Routing"弹出窗口中，你可以选择想要使用的流动性来源。或完全禁用多跳 (multihops)。

注意：禁用多跳可能会导致特定交易对的滑点增加或交易汇率变差。请谨慎操作。

在[此处](../pancakeswap-exchange/fees-and-routes.md#customize-liquidity-sources)了解更多。



## 流动性

### 什么是手续费档位，以及如何选择正确的档位？

在 Exchange v3 中，当你提供流动性时，你可以为同一代币对在几个不同的交易手续费（0.01%、0.05%、0.25% 和 1%）之间进行选择。

例如，对于 CAKE-BNB，可能有一个 0.25% 的交易对，这意味着每笔交易都收取 0.25% 的交易手续费。然而，一些流动性提供者可能会选择以 0.05% 的费率向 CAKE-BNB 交易对提供流动性，从而提供更优的报价并吸引更多的交易量。

对于选择哪种交易手续费配置，没有"正确"答案。这取决于交易对中的代币。通常，波动性较大的代币应设置较高的交易手续费，以更好地补偿波动带来的无常损失。另一方面，像稳定币这样的代币价格波动较小，无常损失较低，因此它们的交易手续费应该较低。

选择代币对时，"Add Liquidity"界面将自动为你选择最受欢迎的手续费档位。



### 为什么我存入的两种代币的美元价值不相等？

在 Exchange V3 中，流动性头寸中的标的资产并不总是具有相等的美元价值。这取决于头寸的价格区间设置和该交易对的当前价格。

事实上，如果你的头寸超出区间，所有代币将被转换为单一资产。此外，你可以向不覆盖当前价格的价格区间提供流动性，并且只存入单一资产。继续阅读以了解更多 ⬇️



### 如果我的流动性头寸超出区间会怎样？

如果当前价格超出你头寸中定义的价格区间，你将不会赚取任何交易手续费奖励。

此外，所有代币将根据价格状况的方向被转换为单一资产。

例如，如果一个 CAKE/BUSD 头寸配置的价格区间为每 CAKE 3 BUSD 到每 CAKE 5 BUSD。当 CAKE 价格高于或等于每 CAKE 5 BUSD 时，头寸中的所有资产将被转换为 BUSD，反之亦然。

请注意，如果价格回到区间内，你将再次开始收到交易手续费奖励。无需任何额外操作。



### 是否总是以较小的区间提供流动性更好？

向较小的价格区间提供流动性将有助于将你的流动性集中到特定的价格区间，提高你在该价格区间内总流动性中的相对份额，从而可能赚取更多的交易手续费奖励。

但是，请记住，只有活跃的流动性头寸才会从交易中赚取交易手续费奖励。这意味着只有当当前交易价格处于流动性头寸中定义的价格区间内时，你才会赚取奖励。



### 有没有办法自动调整我的头寸，使其始终处于区间内并赚取手续费奖励？

PancakeSwap v3 支持通过 Zap 一键存入流动性，在 BNB Chain 和 Ethereum 上可用。

### LP 手续费奖励是否像 Exchange v2 那样自动复利？

不会。

在 Exchange v3 中，你需要手动领取交易手续费奖励。你可以在头寸详情页面进行此操作。你可以在流动性页面找到你所有的 v3 流动性头寸。



### 哪些因素影响 LP APR？

在 Exchange v3 中，LP 手续费奖励 APR 可能因流动性头寸而异。它基于以下因素：

* 交易量\
  \- 更多的交易量产生更多的手续费奖励
* 流动性对手续费档位\
  \- 更高的手续费档位从单笔交易中产生更多的手续费奖励
* 存入的代币数量\
  \- 头寸中更多的代币意味着在总活跃流动性中拥有更大的相对份额，从而从交易中获得更多的交易手续费奖励
* 所选的价格区间\
  \- 对于相同数量的存入代币，较小的价格区间允许更高的集中度，这意味着在总活跃流动性中拥有更大的相对份额，并从交易中获得更多的交易手续费奖励
* 当前活跃的流动性数量\
  \- 如果有更多用户以与你相同的区间存入并集中其流动性，由于在总流动性中的相对份额较小，你将赚取较少的交易手续费
* 流动性头寸是否处于活跃状态\
  \- 只有活跃的流动性头寸才会赚取交易手续费奖励



### 我可以提供 v2 流动性吗？

不再建议提供 v2 流动性。我们建议使用 v3 流动性，以利用新功能提高效率。

如果你想继续添加 v2 流动性：

* 如果该代币对没有 v3 池，或者它在 v2 中的流动性多于 v3 中最大的池。将会出现"Add V2 Liquidity"。只需点击即可切换到添加 v2 流动性
* 或者，在 URL 中使用 `/v2` 以始终使用 v2 流动性提供

### 为什么我无法向刚刚创建的交易对添加流动性？

由于旧版 Exchange V2 的一个 bug（存在于所有 UniSwap V2 分叉中），如果一个交易对满足以下情况，你将无法使用普通的 PancakeSwap 流动性 UI 及其合约调用向该交易对添加流动性：

* 通过在 FactoryV2 上调用 `createPair` 创建，但未存入初始流动性并铸造初始 LP 代币
* 然后，在调用 `sync` 的同时，该交易对中的一种代币被手动转入池合约

{% hint style="info" %}
最近，在 BNB Chain 上的 PancakeSwap Exchange V2 上发现了越来越多此类攻击。&#x20;

我们强烈建议使用我们的 UI 来创建你代币的交易对，在创建交易对时一并添加初始流动性。
{% endhint %}

在 Chefs 努力解决此问题的同时，以下是使用 BscScan 解决此问题的分步指南：

#### 定位池地址及其 BscScan 页面

<div align="left"><figure><img src="https://raw.githubusercontent.com/pancakeswap/pancake-document/en/.gitbook/assets/cannot%20add%20v2%20liquidity-error%20pump.jpg" alt="" width="280"><figcaption></figcaption></figure></div>

如果你的交易对受到影响，你将在错误提示中看到该交易对/池的 BscScan 页面链接。

或者，你可以前往 Factory V2（[Bsc](https://bscscan.com/address/0xca143ce32fe78f1f7019d7d551a6402fc5350c73#readContract)），进入"Read Contract"，"6. getPair"，输入你交易对中两种代币的地址，然后点击"Query"。你应该会在返回字段中看到该交易对的地址。

#### 检查哪种代币已被存入，并手动将另一种代币转入交易对

![](https://raw.githubusercontent.com/pancakeswap/pancake-document/en/.gitbook/assets/image%20%28335%29.png)

从 BscScan 上的代币余额字段，你可以检查哪种代币已被存入池中。通常，应该是配对代币。（如 WBNB、USDT 等……）

确认后，你必须手动将另一种资产转入池合约。你可以在你偏好的钱包应用程序中，将池地址作为接收方来完成此操作。

你可以转入任意数量，但由于这实际上是在向池"捐赠"资产，你将在不铸造流动性代币的情况下把你的资产转入流动性。因此，我们建议将此数量保持在最低限度。

{% hint style="warning" %}
重要：转入代币后，你必须立即在池上调用 `sync()`。
{% endhint %}

你可以通过前往该交易对的 BscScan 页面，进入"Write Contract"，"8. Sync"，然后点击"Write"按钮来完成此操作。在执行交易之前，你需要连接你的钱包。

交易确认后，你就可以在 PancakeSwap UI 上添加后续的流动性。

#### 如果我想定义启动价格怎么办？

你必须在转入代币和修复池的同时，将池调整到启动价格。

要转入的数量可以使用以下公式计算：

* `tokenInside`：已经转入池中的代币。通常应该是配对代币。（如 WBNB、USDT 等……）
* `tokenToSend`：即将发送到池中的代币。通常应该是你的项目代币
* `tokenInside.price`：tokenInside 的美元价格
* `tokenToSend.price`：tokenToSend 的美元价格（启动价格）
* `pool`：V2 池

使用以下公式：

`amountToSend = tokenInside.balanceOf(pool) / tokenInside.decimal() * tokenInside.price / tokenToSend.price * tokenToSend.decimal()`

如果结果小于 0（通常发生在启动价格非常大的时候。你可能需要先向池中存入更多 `tokenInside`）



### 如何管理 Stable LP 和旧版 v2 LP？

你可以像往常一样通过前往[流动性](https://pancakeswap.finance/liquidity)页面来管理它们。



### 为什么我在启用/授权之前需要重置 USDT 的授权？

在以太坊主网上操作时，USDT 代币遵循不同的逻辑来管理授权和代币额度。&#x20;

因此，当授权额度过低时，它要求你在设置新的授权之前先重置授权。
