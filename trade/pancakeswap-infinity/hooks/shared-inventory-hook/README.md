# Shared Inventory Hook

PancakeSwap公式のShared Inventory Hook（SIH）は、トークンを共有するすべてのプールにまたがって、単一の資本プールでマーケットメイクを行えるように設計されています。プールごとに別々の流動性をロックする必要はありません。トレーダーはより深い気配値と低いプライスインパクトを得られ、流動性プロバイダーは同じカバレッジをより少ない資本で提供できます。

PancakeSwapのコアチームによって開発されたこのHookは、在庫を分散させることなく、複数のペアをオンチェーンで提示したいアセット発行体やマーケットメイカー向けに最適化されています。

#### 🔍 なぜShared Inventoryなのか？

従来の方法で複数のペアに流動性を提供するには、個別のプールに専用の資本をロックする必要があり、その大半は取引と取引の合間に遊休状態となります。SIHでは代わりに、トークンごとに1つの残高を保持し、スワップが必要とするときにのみ流動性として投入します。そのため、同じ資本で、そのトークンを共有するすべてのプールを支えることができます。

#### 📊 他のモデルとの違いは？

従来の集中流動性では、元本の全額を1つのプールに投入する必要があります。仮想残高の決済レイヤーのような、プールをまたぐ他の手法は、通常AMMの外側に位置しており、流動性がオンチェーンのプール深度として見えず、アグリゲーターによって直接ルーティングされない場合があります。

SIHの流動性は、スワップのたびにHookによってPancakeSwap Infinity CLAMMプールに出入りするため、ルーターが確認して約定できる本物のプール深度として表示されます。

#### ⚙️ 仕組み

* **ジャストインタイム（JIT）注入**\
  各スワップの前に、Hookは設定された集中流動性ポジションをプールにミントし、スワップの実行後にバーンして純額を決済します。ポジションは1回のスワップの間だけ存在するため、残高はすぐに次の、それを必要とするプールで利用できます。
* **1つの残高、多数のプール**\
  在庫はHook自身のトークン残高であり、プールごとの預け入れはありません。複数のプールで使用されるトークンは、そのすべてで共有されます。

{% hint style="success" %}
これにより、プールが提示する深度と、プールが直接保有する資本が切り離されます。資金を備えたHookは、トークンを共有する複数のプールにわたって、深くタイトな流動性を提示できます。
{% endhint %}

* **設定可能なHook**\
  Hookは、対応するプールごとに、価格レンジと深度について独立した調整可能な設定を保持します。レンジの移動には設定の更新だけが必要なため、変動する基準価格を中心に気配値を再調整するのも簡単です。

#### 📌 重要なポイント

* 1つの共有トークン残高が、そのトークンを使用するすべてのプールを支えます。新しいプールを追加しても、新たな元本は必要ありません。
* 完全にオンチェーンで、コンポーザブルです。SIHの流動性は本物のプール深度であり、PancakeSwapでもサードパーティのアグリゲーターでもルーティングできます。
* トレーダーは大きな注文でもより深い気配値と低いプライスインパクトを得られ、オペレーターは従来の資本のごく一部で、同じ取引手数料を得られます。
