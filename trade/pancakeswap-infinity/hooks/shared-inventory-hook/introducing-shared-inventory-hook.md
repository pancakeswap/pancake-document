# Shared Inventory Hookのご紹介

<figure><img src="https://raw.githubusercontent.com/pancakeswap/pancake-document/en/.gitbook/assets/image%20%2816%29.png" alt=""><figcaption></figcaption></figure>

5つのペアを見積もるのに、5倍の資本が必要であるべきではありません。しかしオンチェーンでは、すべての資産発行体がその条件を受け入れています。流動性がペアごとに紐づいているため、新しいペアを追加するたびに別の資本を投入する必要があり、その大半は、まさにそのペアが正確な価格レンジ内で取引されるまで、何も生まないまま眠っています。新しいペアを見積もりたいたびに新たな資本をLPとして投入することになり、その資本はその1つのペアにロックされ、他の場所では使えません。

Shared Inventory Hook(SIH)は、この紐づけを断ち切ります。PancakeSwap Infinityの最新のフックであり、資本効率のために作られた初めてのフックです。

_💡 おさらい:フックとは、Infinityのプールに組み込まれ、スワップの途中でカスタムロジックを実行するスマートコントラクト(アドオンのようなもの)です。新たな取引の場を立ち上げる必要はありません。_

では、どのように機能するのでしょうか?

すべてのプールに別々のスタックをロックする代わりに、RWA資産の発行体は**1つの共有インベントリ**に資金を供給し、Shared Inventory Hookがそこから、取引が行われているペアに対して、スワップが発生するその瞬間にジャストインタイムで流動性を見積もります。厨房のすべての料理を、料理ごとの別々の食材庫ではなく、1つの食材庫でまかなうイメージです。1つの残高が、多数の残高の役割を果たします。

この1つの転換が、SIHを資本効率の高いものにしており、次の3つの形で現れます。

* **資本が常に稼働し続けます。** フックのインベントリからの流動性はスワップ時にジャストインタイムで注入されるため、遊休状態にならず、実際に稼働して手数料を生み出します。
* **1つの残高で、複数のペアから手数料収益を得られます。** 1つのインベントリが、対応するすべてのペアで収益を生み出すため、投入する資本をはるかに抑えながら手数料フローを獲得できます。
* **プライスインパクトが小さくなります。** スワップ時に見積もられる流動性がより厚いため、SIHが最良価格を提示している場合は、大口取引でもプライスインパクトが小さくなります。
* **資本効率が向上します。** 一度資金を供給すれば、同じ資本がSIH対応のすべてのペアの流動性を支えます。さらに、新しいペアでも資本を追加することなくSIHを有効にできます。

_**重要:**_

_SIHは、インベントリがスワップの瞬間にのみ稼働するため、通常のLPポジションと比べて価格変動の影響を受けにくくなっています。ただし、リスクがないわけではありません。オペレーターは依然として、市場とともに価値が変動するインベントリを保有しています。あらゆるオンチェーン戦略と同様に、結果は取引量、インベントリ、ヘッジ、市場環境によって左右されます。_
